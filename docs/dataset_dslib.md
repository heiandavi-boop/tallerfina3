# DSLIB Dataset Card

## Source and version

DSLIB, also called PSLIB in the publisher's repository, is the Dynamic Scheduling empirical project database maintained by the Operations Research & Scheduling group associated with Ghent University. This audit uses release `DSLIB_v3.4`, published September 2026, from the [official release](https://github.com/MarioVanhoucke/DSLIB-Dynamic-Scheduling-Empirical-Project-Library/releases/tag/DSLIB_v3.4). The publisher describes the records as empirical real-world project data for baseline scheduling, risk analysis, and project control.

The publisher's README reports 231 projects. The release archive contains 231 per-project Excel workbooks and 231 Project Card files. The archive is retained locally at `data/raw/dslib/DSLIB3.4.zip`; the extraction and manifest are generated by `scripts/download_dslib.py` and `scripts/audit_dslib.py`. The archive SHA-256 is `19f87632c589f5d49f72b5f071992efc6379df2beb35f1efd3a60ac1381dc277`.

The publisher's repository/release does not specify a data license. The local raw archive is Git-ignored and must not be redistributed without permission. Cite Batselier and Vanhoucke (2015), DOI [10.1016/j.ijproman.2014.09.004](https://doi.org/10.1016/j.ijproman.2014.09.004), and the publisher's current release page when using the data. The publisher identifies the 2015 article as the primary dataset reference and asks users of the expanded collection to cite the associated books as relevant.

## Preparation and exclusions

Raw files are never edited by the pipeline. Re-extraction is skipped when the versioned source directory already exists. The adapter writes `data/interim/dslib/project_samples.csv`, `temporal_snapshots.csv`, and `data/processed/dslib/model_samples.csv`, plus a preparation manifest with source/data hashes.

Project-level training rows contain only planned duration in calendar days and BAC. Project names, submitter names, final outcome summary metrics, and manager-identifying data are excluded. Target values are actual duration minus planned duration (days) and `(actual_cost - BAC) / BAC`. Negative delays (early finish) and negative cost overruns (under-budget execution) are preserved.

The aggregate sheet's final Duration and Cost fields are used as targets only. They are never snapshot features. The currently trained regressors use one baseline row per project; 151 projects satisfy both required features and the corresponding observed target for each regression. The EVM snapshot adapter requires observed project-summary EV, PV, AC, and percent complete, plus a tracking date before baseline finish. After that filter, only 13 projects/snapshots per regression are eligible, which is not sufficient for the temporal model or 20/40/60/80% evaluation. See `reports/empirical/leakage_audit.json`.

## Known issues

The collection is small, heterogeneous, observational, and subject to reporting/completeness bias. Currency units and project context vary; the source does not provide a consistent project methodology or Health label. Sector/type is not used as a model feature because a verified, stable mapping has not been established. No records are generated, augmented, or combined with Mendeley.
